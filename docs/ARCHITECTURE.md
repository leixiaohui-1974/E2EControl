# 架构设计文档

## 概述

E2EControl采用分层解耦架构，将系统划分为5个核心层次，每层职责明确、接口清晰，支持独立开发和渐进式集成。

## 系统分层架构

```
+===================================================================+
||                    L5: 用户交互层                                 ||
||          自然语言解析 | REST API | Web界面 | 预警接口             ||
+===================================================================+
                              |
+===================================================================+
||                    L4: 智能决策层 (Brain)                         ||
||         场景识别(18种) | 策略选择(7种) | 知识库 | 风险评估        ||
+===================================================================+
                              |
+===================================================================+
||                    L3: 优化控制层 (DMPC)                          ||
||         ADMM分布式优化 | 多池协调 | 前馈控制 | 约束管理           ||
+===================================================================+
                              |
+===================================================================+
||                    L2: 数字孪生层 (Twin)                          ||
||         物理本体 | 智能感知 | 鲁棒求解器 | 仿真引擎              ||
+===================================================================+
                              |
+===================================================================+
||                    L1: 健壮保障层 (Shield)                        ||
||         异常检测 | 故障诊断 | 自愈控制 | 降级管理                 ||
+===================================================================+
```

## 各层详细设计

### L1: 健壮保障层

健壮保障层是系统的安全底座，负责异常感知、故障定位和自主恢复。

**模块组成：**

| 模块 | 文件 | 职责 |
|------|------|------|
| 基础检测框架 | `phase4/anomaly_detection/base_detector.py` | 检测器抽象基类与通用接口 |
| 统计检测器 | `phase4/anomaly_detection/statistical_detectors.py` | 3-Sigma、CUSUM、EWMA、Range、RateOfChange |
| 机器学习检测器 | `phase4/anomaly_detection/ml_detectors.py` | Isolation Forest、One-Class SVM、LOF、Autoencoder |
| 深度学习检测器 | `phase4/anomaly_detection/dl_detectors.py` | LSTM-AE、GRU、VAE |
| 集成检测器 | `phase4/anomaly_detection/ensemble_detector.py` | Voting、Weighted、Stacking融合策略 |
| 故障诊断引擎 | `phase4/fault_diagnosis/diagnosis_engine.py` | 规则引擎、特征匹配、根因分析 |
| 故障隔离 | `phase4/self_healing/isolation_strategy.py` | 4种隔离动作 |
| 降级管理 | `phase4/self_healing/degraded_mode.py` | 7种降级运行模式 |
| 恢复管理器 | `phase4/self_healing/recovery_manager.py` | 7种恢复策略 |
| 自愈集成 | `phase4/self_healing/self_healing_system.py` | 10步闭环自愈 |

**自愈闭环流程：**

```
故障检测 --> 故障诊断 --> 影响评估 --> 故障隔离 --> 模式降级
  (<5s)      (<1s)       (<1s)      (<30s)      (<10s)
    ^                                               |
    |                                               v
历史记录 <-- 模式恢复 <-- 效果验证 <-- 执行恢复 <-- 生成计划
              (<10s)     (30-120s)   (60-600s)    (<5s)
```

**多层次防御架构：**

```
预防层（预测性维护与参数监控）
    |
检测层（15+异常检测算法并行运行）
    |
诊断层（5大故障类型 x 规则引擎匹配）
    |
响应层（自动隔离 + 模式降级）
    |
恢复层（智能恢复 + 效果验证）
```

### L2: 数字孪生层

数字孪生层构建了高精度的物理-信息-控制耦合仿真环境。

**模块组成：**

| 模块 | 文件 | 职责 |
|------|------|------|
| 物理本体 | `digital_twin/physics/single_channel_fidelity.py` | 20km渠池、圣维南方程、5维状态演化 |
| 智能感知 | `digital_twin/perception/intelligent_observer.py` | 参数辨识、FDIA防御、多维风险扫描 |
| 鲁棒求解器 | `digital_twin/control/single_pool_admm.py` | 经济优化、动态约束、风险自适应 |
| 仿真引擎 | `digital_twin/scenarios/deep_dive_simulation.py` | 6阶段深度仿真场景 |
| 可视化大屏 | `digital_twin/visualization/dashboard.py` | 3x3九维监控面板 |

**物理模型5维状态空间：**

```
状态向量 X = [Z, Q, C, T_ice, n_roughness]

  Z          - 水位（m），由圣维南方程驱动
  Q          - 流量（m3/s），连续性方程
  C          - 污染物浓度（mg/L），对流扩散方程
  T_ice      - 结冰温度指标，热力学方程
  n_roughness - 曼宁粗糙度系数，空间异质性
```

**感知-控制数据流：**

```
物理本体（状态演化）
    |
    v
智能感知层
  |-- 参数辨识：在线学习粗糙度 n
  |-- 安全防御：FDIA检测 + 物理一致性探针
  |-- 风险扫描：边坡 + 水质 + 网络 + 视觉
  |-- 约束生成：动态安全约束下发
    |
    v
鲁棒ADMM求解器
  |-- x-update：效率优化（水位跟踪 + 能耗最小 + 平滑性）
  |-- z-update：安全投影（动态约束）
  |-- 电价调度：峰谷平分时策略
```

### L3: 优化控制层

基于ADMM的分布式模型预测控制，实现多渠池协调优化。

**核心算法：**

- **MPC（模型预测控制）**：滚动优化，10步预测时域
- **ADMM（交替方向乘子法）**：分布式求解多池耦合问题
- **Over-relaxation**：加速ADMM收敛（提速40%）
- **Warm-start**：利用历史解加速当前求解
- **前馈控制**：基于需求/天气/上游预测的前馈补偿

**多目标优化：**

```
min  w1 * ||Z - Z_ref||^2    水位跟踪
   + w2 * ||dQ||^2           流量平滑
   + w3 * E_cost             能耗成本
   + w4 * R_safety           安全惩罚
   + w5 * C_pollution        污染控制

s.t. Z_min <= Z <= Z_max     水位约束
     0 <= Q <= Q_max         流量约束
     |dQ| <= dQ_max          变化率约束
```

### L4: 智能决策层

场景感知与策略选择的核心引擎。

**场景识别体系（7大类62个工况）：**

| 场景大类 | 工况数 | 典型场景 |
|---------|--------|---------|
| S1. 正常运行 | 12 | 日常供水、高峰需求、经济调度 |
| S2. 防洪调度 | 10 | 暴雨预警、洪峰过境、超标洪水 |
| S3. 干旱应对 | 8 | 水源不足、限量供水、旱涝急转 |
| S4. 冰期运行 | 8 | 冰下输水、冰塞风险、融冰过渡 |
| S5. 污染应急 | 8 | 紧急切断、污染追踪、多源污染 |
| S6. 设备故障 | 10 | 传感器失效、闸门卡死、多设备故障 |
| S7. 安全攻击 | 6 | FDIA数据篡改、DoS攻击、复合攻击 |

**决策流程：**

```
传感器数据 --> 特征提取 --> 场景识别(规则70%+特征30%)
                               |
                               v
                          策略选择(7种)
                               |
                               v
                      参数自适应调整 --> MPC控制器
```

### L5: 用户交互层

提供多种用户接入方式。

- **自然语言接口**：中文指令解析，语义理解
- **REST API**：13个端点，支持同步/异步仿真
- **Web界面**：实时监控大屏（开发中）
- **预警接口**：外部预警信号接入


```
传感器数据 --> 异常检测 --> 故障诊断 --> 隔离策略
                                         |
                                         v
                                    降级模式 --> 恢复计划 --> 执行恢复
                                         |
                                         v
                                    效果验证 --> 模式恢复/升级策略
```

## 配置管理

系统配置集中在 `config.yaml`，主要包括：

- **仿真参数**：时间步长、总时长、渠池面积
- **MPC参数**：预测时域、权重矩阵、约束限制
- **监控参数**：告警阈值、日志级别
- **API参数**：端口、调试模式、CORS设置
- **数据库**：SQLite存储路径、优化选项

## 扩展性设计

系统采用松耦合模块化设计，支持以下扩展方式：

1. **新增检测算法**：继承 `BaseDetector` 基类即可注册新检测器
2. **新增故障类型**：在故障类型库中添加新的规则条目
3. **新增恢复策略**：在恢复管理器中注册新策略
4. **新增仿真场景**：按场景模板编写新场景配置
5. **新增API端点**：在 `api.py` 中注册新路由
