# 原有测试严格复验框架

## 1. 目标

本文件用于重新界定仓库内既有测试的“证明力”。

核心问题不再是“测试是否跑过”，而是：

1. 这些测试是否真的证明了模型精度可靠。
2. 这些测试是否真的证明了控制效果良好。
3. 这些测试是否只是结构、接口、流程层面的冒烟通过。
4. 这些测试是否能形成正式验收证据链。

## 2. 五层证明体系

### 2.1 L0 冒烟与结构正确性

目标：确认模块可导入、对象可构造、流程可跑通、报告可生成。

典型证据：

- 导入成功
- 枚举/配置/数据结构字段存在
- 测试执行器能跑完
- 结果文件与报告文件可生成

严格判定：

- 只能证明“系统未立即崩溃”
- 不能直接证明模型精度
- 不能直接证明控制效果

### 2.2 L1 数值物理精度

目标：确认水力学模型在可解释工况下与解析解/黄金真值一致。

强制指标：

- 质量守恒误差
- 稳态解析解偏差
- 波速到达时间偏差
- 基础物理合理性
- 黄金真值比对误差

建议严格阈值：

- `M1` 质量守恒误差：`<= 2.0%`
- `M2` 稳态解析解偏差：`<= 2.0%`
- `M3` 波速到达时间偏差：`<= 20.0%`
- `M4` 黄金真值 gauge RMSE：`<= 0.020 m`
- `M5` 黄金真值 final profile RMSE：`<= 0.005 m`
- `M6` 不允许 `NaN/Inf/负水深/明显爆炸`
- `M7` 至少 3 类基准工况：稳态、阶跃传播、长时守恒

说明：

- 当前仓库已经具备一条较强的 L1 链路，但场景覆盖仍偏窄。

### 2.3 L2 控制效果

目标：确认控制器不仅能输出动作，而且能在闭环下产生可接受的动态效果。

强制指标：

- `C1` 跟踪积分误差：`IAE` / `ITAE`
- `C2` 稳态误差
- `C3` 调节时间
- `C4` 超调量
- `C5` 约束违反次数/持续时间
- `C6` 扰动抑制比
- `C7` 控制动作平滑性与总控制能量
- `C8` 多池协调误差

建议严格阈值：

- `C1` `IAE` 与基线控制器比较不劣化
- `C2` 稳态误差：`<= max(0.05 m, 2% setpoint)`
- `C3` 调节时间：按场景定义上限，不再只看“最终有改善”
- `C4` 超调量：`<= 10%`
- `C5` 安全约束违反次数：`0`
- `C6` 扰动抑制比：`>= 2.0`
- `C7` `Δu` 与总控制能量都需受限
- `C8` 多池协调最大偏差：按网络等级单独设限

说明：

- 只要存在“始终通过、仅靠评分区分好坏”的控制测试，都不能作为 L2 正式证据。

### 2.4 L3 HIL / 系统级场景效果

目标：确认系统在多类场景、扰动、故障注入下仍满足安全和性能边界。

强制指标：

- `S1` 场景通过率
- `S2` 安全边界保持
- `S3` 异常恢复时间
- `S4` 人工接管频率
- `S5` 数字孪生/物理/控制链路一致性
- `S6` 实时性与算力预算

建议严格阈值：

- `S1` 分类场景通过率按难度分层统计
- `S2` 关键安全边界违反次数：`0`
- `S3` 故障恢复时间：按场景设限
- `S4` 人工接管只允许在允许级别内发生
- `S5` 不能只看“报告生成成功”
- `S6` 需要记录控制求解失败率、fallback 发生率

### 2.5 L4 验收证据与可追溯性

目标：确保复验结果能进入正式验收，而不是一次性运行记录。

强制要求：

- 固定命令
- 固定版本
- 原始结果文件
- 关键摘要文件
- 人工判读
- 复核与审批签字

## 3. 原有测试的严格复验判断规则

### 3.1 有效

满足以下至少一项：

- 直接对解析解或黄金真值做误差判定
- 直接对闭环性能指标做阈值判定
- 直接对安全/约束/恢复时间做硬门槛判定

### 3.2 部分有效

满足以下特征之一：

- 记录了性能分数，但通过阈值明显偏宽
- 做了场景仿真，但只验证结构与流程
- 有闭环运行，但求解器/控制器存在 fallback 污染

### 3.3 仅冒烟

满足以下特征之一：

- 只验证导入、字段、对象构造、文件生成
- 只验证“结果存在”
- 只验证 pass rate/score 字段存在，而不审查其物理含义

### 3.4 无效或不应作为精度/效果证据

满足以下特征之一：

- `passed=True` 被硬编码或基本恒真
- 以简化占位值代替真实物理/控制量
- 关键依赖缺失时退化到 fallback，但测试仍视作通过

## 4. 本轮复验优先级

### P0 必须先完成

- 模型精度：L1 全部硬门槛化
- 原有 physics / control / HIL 测试的证明力分层
- 把“只会跑通”的测试从验收证据中剥离

### P1 随后推进

- 控制效果指标自动化
- fallback 发生率统计
- 多池协调与故障恢复的硬门槛化

### P2 最后推进

- 覆盖更多工况族
- 引入更长时、多扰动、跨季节场景
- 将复验矩阵与验收矩阵完全联动
